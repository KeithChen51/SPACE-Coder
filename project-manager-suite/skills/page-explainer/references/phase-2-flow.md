# Phase 2: 流程梳理

> 本文件在进入 Phase 2 时由 SKILL.md 指令加载。

## 目标

以用户任务为维度，梳理跨页流程。流程文件同时承担所有产物的索引职责。

## 执行步骤

1. 从 BRD 中提取所有核心用户场景
2. 对每个场景，梳理用户完成该任务需要经过的页面路径
3. 标注每个步骤对应的页面路由（必须与 page-delivery 一致）
4. 识别流程断点：是否有走不通的路径、缺失的页面、不合理的跳转

## 产物结构

文件名：`explainer-flow-<slug>.md`

```markdown
# 用户流程与产物索引 - <项目名称>

> 生成时间: YYYY-MM-DD HH:MM
> Skill: page-explainer
> 路径: C+B / 纯B

## 产物索引

| 产物 | 文件路径 |
|------|---------|
| C 端交互描述 | <路径> |
| B 端交互描述 | <路径> |
| B 端权限矩阵 | <路径> |

## 用户流程

### 流程 1: <任务名称>

**用户角色**: <角色>
**目标**: <用户要完成什么>

| 步骤 | 页面 | 路由 | 用户动作 | 结果 |
|------|------|------|---------|------|
| 1 | <页面名> | <路由> | <做什么> | <去哪/看到什么> |
| 2 | ... | ... | ... | ... |

### 流程 2: <任务名称>
<!-- 同上结构 -->
```

## 注意

- 流程按用户任务组织，不按页面组织
- 每条流程必须从入口走到出口，不能有断点
- 流程中引用的路由必须与 page-delivery 一致
