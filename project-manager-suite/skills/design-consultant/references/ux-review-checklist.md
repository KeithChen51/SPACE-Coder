# UI/UX 核查清单

本文件 vendored 本地规则，吸收 Web Interface Guidelines 的核心规则，并保留部门后续沉淀空间。不要运行时远程拉取规则。

## 输出格式

默认按严重度排序：

```markdown
## P1
- [文件/位置] 问题：影响主流程或可访问性。建议：...

## P2
- [文件/位置] 问题：影响效率、一致性或移动端。建议：...

## P3
- [文件/位置] 问题：体验 polish 或文案细节。建议：...
```

如果是代码 review，尽量带文件和行号。如果是设计方案 review，带页面区域或组件名。

## 可访问性

- icon-only 按钮必须有 `aria-label`。
- 表单控件必须有 label 或 `aria-label`。
- 可点击元素优先使用 `<button>` 或 `<a>`，不要用 `<div onClick>`。
- 图片必须有 `alt`，装饰图使用 `alt=""`。
- 装饰图标使用 `aria-hidden="true"`。
- 异步更新如 toast、校验结果需要合适的 live region。
- 标题层级要合理，不跳级制造结构混乱。
- 键盘可操作，焦点顺序符合视觉顺序。

## 焦点状态

- 所有交互元素必须有 visible focus。
- 禁止 `outline: none` 后没有替代 focus 样式。
- 优先使用 `:focus-visible`。
- 复合控件可使用 `:focus-within` 组织焦点态。

## 表单

- 输入框必须有明确 `name` 和 `autocomplete`。
- 邮箱、电话、URL、数字使用正确 `type` 和 `inputmode`。
- 不要阻止粘贴。
- label 点击区域应能聚焦控件。
- 邮箱、验证码、用户名等可关闭 spellcheck。
- submit 按钮在请求开始前保持可点，请求中显示 loading。
- 提交失败后聚焦第一个错误。
- 错误文案必须说明修复路径。
- 有未保存内容时，离开页面要提醒。

## 动效

- 支持 `prefers-reduced-motion`。
- 优先动画 `transform` 和 `opacity`。
- 不使用 `transition: all`。
- popover、dropdown 要有合理 transform-origin。
- 动画应可中断。
- 高频操作不做强动画。

## 内容与排版

- 标题尽量避免孤行和难看的换行。
- 数字、金额、对比列使用 tabular nums。
- 长文本容器必须处理截断、换行或展开。
- flex 子项如需截断，应设置 `min-width: 0`。
- 文案使用具体动词，按钮不要只写“继续”。
- 错误文案不要只说失败，要给下一步。

## 图片与媒体

- 图片设置明确 width/height，避免 CLS。
- 首屏关键图设置优先加载。
- 非首屏图片使用 lazy loading。
- 不用低质量装饰图掩盖真实产品状态。

## 性能

- 大列表超过 50 项考虑虚拟化或分页。
- render 中不要做布局读取。
- 控制型输入要保证每次输入足够轻。
- 字体加载要有 `font-display: swap`。
- 避免过重阴影、模糊和长列表动画。

## 导航与状态

- 筛选、分页、tab、展开面板等重要状态应可恢复，必要时进入 URL。
- 链接使用 `<a>` 或框架 Link，保留 Cmd/Ctrl 点击。
- 危险操作需要确认或撤销窗口。
- 页面刷新后不应丢失关键上下文。

## 触摸与移动端

- 交互目标足够大。
- 抽屉、弹窗处理 overscroll。
- 移动端避免自动聚焦导致键盘遮挡。
- 处理 safe area。
- 防止横向溢出。
- 表格、筛选、批量操作在窄屏有明确替代布局。

## 暗色模式与主题

- 暗色主题设置 `color-scheme: dark`。
- 原生 select、input 在暗色模式下颜色明确。
- 主题切换不能造成局部反相混乱。
- 图表颜色在明暗模式下都可读。

## 国际化与数据格式

- 日期使用 `Intl.DateTimeFormat`。
- 数字、金额使用 `Intl.NumberFormat`。
- 不用 IP 判断语言。
- 品牌名、代码 token、编号可加 `translate="no"`。

## 状态完整性

每个关键模块必须检查：

- loading
- empty
- error
- success
- disabled
- permission denied
- partial data

只有成功态的页面不能视为完成。

## 历史项目经验补充区

以下经验已获用户确认，可以作为后续 UI/UX review 的本地规则使用。

### 高密度后台与数据工作台

- 高密度后台的外层页面不应整体滚动到分页不可见；结果区应内部滚动，分页保持可见。
- 宽表移动端必须有记录卡片、关键列固定或明确横向滚动策略，不能让页面整体横向溢出。
- 表格分页需要页码输入、范围校验、前后翻页；移动端可隐藏首页/末页/跳转按钮，但保留页码输入。
- 筛选、分页、排序、tab 等运营上下文刷新后不应丢失，优先同步到 URL 或持久状态。
- 明细长表桌面端可以使用固定视口工作台；移动端应恢复自然页面滚动。

### 组件与工程守门

- 业务页面不应绕过共享 DataTable、Select、Dialog、IconButton 等组件，除非项目尚无对应共享组件。
- 图标库应集中入口，不要在业务页面直接导入多个图标来源。
- CSS token 需要检查未定义引用；出现 `var(--*)` 但无定义时，应视为 P1/P2 设计系统一致性问题。
- 业务代码中散落 hex/rgb/hsl/oklch 色值，通常说明 token 没有被正确使用。
- 暂缓组件不得被提前抽成公共 token 或公共组件，否则会把未决样式固化。

### Agent 与过程型界面

- 运行中、审批、工具调用、产物不能混成同一种卡片；它们应有不同信息层级。
- 审批阻塞态应只有一个主视觉位置，不能在输入区、消息流、toast 里重复强提醒。
- 工具调用和后台记录应是低强调事件行，不应抢正文和审批的注意力。
- 产物、Diff、同步冲突文件行应有统一文件类型图标或等价识别方式。
- Task Bar 收起态应贴近输入区，展开态应展示已完成、执行中和未开始步骤。

### 宿主环境

- 嵌入宿主环境的产品应先像宿主，再表达自有品牌。
- 普通设置页、列表、工具栏优先使用宿主变量、宿主密度和宿主控件。
- 品牌只应出现在身份、onboarding、空状态、助手身份或外部发布物料中。
- 不要把营销页 hero、大渐变、玻璃拟态、重阴影直接塞进插件或宿主设置界面。
