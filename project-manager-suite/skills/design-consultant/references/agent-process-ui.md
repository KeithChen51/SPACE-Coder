# Agent 过程型 UI

适用：AI 助手、自动化执行、工具调用、审批、Task Bar、产物、Diff、同步冲突、长任务运行状态。

目标：让用户知道“谁在行动、现在到哪一步、是否需要我确认、产生了什么结果”，同时避免把过程信息做成一堆重卡片。

## 信息层级

| 层级 | 作用 | 默认视觉 |
| --- | --- | --- |
| 正文 | 用户真正要读的回答或结果 | 文档流 |
| 身份 | 谁在回答、是否完成、耗时 | 小身份行 |
| 过程步骤 | 当前任务阶段 | 可收起的一行步骤 |
| 工具调用 | 运行记录 | 低强调事件行 |
| 审批 | 阻塞用户继续 | 输入区强提醒 |
| 产物 | 文件、Diff、链接 | 文件行 |
| 运行中 | 当前正在执行 | 单行 running surface |

## 助手消息

规则：

- 用户消息可以是右侧气泡。
- 助手消息优先是文档流，不模仿用户气泡。
- 简单结果显示“已思考/已完成 + 用时”，不展开过程。
- 复杂任务结果显示“已完成工作 + 用时 + 展开入口”，过程默认收起。
- 每个过程步骤可展开，展开后只显示该步骤相关工具调用。
- 不要在展开区再加一个“过程”标题。

## Task Bar

用途：任务已经分步骤执行，需要让用户看到进度。

规则：

- 收起态贴住输入框上方。
- 展开态展示已完成、执行中、未开始步骤。
- 不占用输入内容区。
- 正在执行步骤用整体弱背景，不靠大图标抢注意力。
- 主文本单行显示，宽度不足时省略。

## 审批强提醒

规则：

- 审批是输入区状态，不在消息流、toast、独立卡片里重复强提醒。
- 文案说明等待什么、确认后会发生什么。
- 主按钮是明确继续动作，如“应用修改”。
- 次按钮视觉弱一些，如“不应用”。
- 审批等待不要呼吸或闪烁。
- Diff 是审批子系统，不另起强提醒风格。

## 工具调用与事件行

工具调用、同步日志、后台记录、队列提示使用同一低强调事件行：

```text
[icon] 工具名 · 做了什么 · 状态/耗时
```

规则：

- 不做成大卡片。
- 不承担主阅读内容。
- 细节只在展开后显示。
- 长内容截断或进详情。

## 产物与文件类型

产物、Diff 文件行、同步冲突文件行共用文件类型图标：

- Markdown / 文档。
- Canvas / 白板。
- HTML / 预览。
- 代码。
- 普通文件。

已选中的上下文 token 可以不显示文件类型图标，以减少噪音。

## 运行中表面

规则：

- 使用低幅度背景、进度条或扫光。
- 尊重 `prefers-reduced-motion`。
- 不让大块内容持续动。
- 审批等待不动。
- 高频操作不做强动效。

## 禁止项

- 不把工具调用做成重卡片。
- 不把所有状态都染成品牌色。
- 不在多个位置重复同一个审批。
- 不把执行过程和计划拆成多套视觉系统。
- 不用机器人、吉祥物或泛 AI 图标替代产品身份。
