# 宿主原生 UI 规则

适用：产品嵌入 Obsidian、VS Code、浏览器插件、企业套件、第三方平台、CMS、CRM 或大型系统内。

核心原则：先像宿主，再表达自己。用户打开的是宿主产品中的功能，不是另一个独立 SaaS 页面。

## 模式判断

| 模式 | 使用场景 | 规则 |
| --- | --- | --- |
| Host-Native | 设置、列表、表单、工具栏、普通弹窗 | 使用宿主变量、控件和密度 |
| Branded Identity | 插件入口、onboarding、空状态、助手身份、文档 | 小面积品牌信号 |
| Standalone Future | 官网、外部演示、独立应用、发布物料 | 可使用完整品牌系统 |

不要把 Standalone Future 的视觉语言带进 Host-Native 日常界面。

## 主题与变量

优先使用：

- 宿主提供的背景、文本、边框、交互、语义色变量。
- `currentColor` 驱动图标。
- `color-mix()` 生成轻量 hover、selected、running 背景。

避免：

- 写死浅色或深色背景。
- 大面积品牌色背景。
- 装饰性渐变、发光、玻璃拟态。
- 只在默认主题下成立的对比度。
- 全局覆盖宿主内部 DOM。

## 密度与形状

- 普通控件圆角 4-8px。
- 分组面板圆角 8-12px。
- 胶囊只用于 badge、counter、token。
- 不要卡片套卡片。
- 设置、列表和工具栏应保持紧凑扫描效率。

## 品牌出现规则

允许：

- 顶部身份区域出现一次 logo 或 wordmark。
- 助手身份、小尺寸状态头像、空状态出现小标识。
- onboarding 或文档页使用轻品牌。

避免：

- 每个设置组都放品牌。
- 每个普通按钮都使用品牌色。
- 把品牌图标当作普通功能图标。
- 在宿主设置页做 hero 或宣传文案。

## 组件优先级

1. 宿主原生组件。
2. 项目已有 native kit / settings kit。
3. 共享组件。
4. 新组件。

新增组件前先问：

- 宿主是否已有这个控件？
- 是否破坏明暗主题？
- 是否需要第三方主题兼容？
- 是否只是为了“看起来更像自己的品牌”？

## 检查清单

- [ ] 已判定 Host-Native / Branded Identity / Standalone Future。
- [ ] 普通 UI 使用宿主变量。
- [ ] 品牌只出现在身份位置。
- [ ] 没有大渐变、玻璃、重阴影和营销页结构。
- [ ] 明暗主题和第三方主题可读。
- [ ] 新 CSS 有作用域，不全局污染宿主。
- [ ] 危险操作放在相关组末尾，并要求确认。
