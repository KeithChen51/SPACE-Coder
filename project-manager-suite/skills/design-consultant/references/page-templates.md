# 页面模板

本文件沉淀可复用页面结构。它不是视觉稿，而是 AI 给前端建议或实现时优先使用的信息架构。

## Composition Kit 输出格式

当用户要求设计页面、流程、前端结构或交互方案时，先输出 Composition Kit。它的作用是把“页面结构、组件选择、状态覆盖和工程守门”一次性对齐。

```text
Composition Kit
- Route: [default/customize/design-system/review] + [横向模式]
- Page template: [选择本文件中的模板]
- Frame: [App shell/工作台/文档流/宿主设置页/移动端自然滚动]
- Blocks: [页面区块，按阅读和操作顺序排列]
- Component families: [从 component-system.md 或 component-manifest.json 选择]
- States: [loading/empty/error/success/disabled/permission denied/partial data]
- Responsive contract: [桌面、窄屏、移动端的区域变化]
- HTML preview decision: [yes/no + reason]
- Acceptance commitments: [稳定 ID + source/requirement/required/implementationStatus/codeRefs/scenarioIds/waiver]
- Enforcement: [token/CSS/shared component/icon/a11y checks]
```

为需要落实和验收的关键结构、交互、状态与响应式行为分配稳定 ID。进入实现时，把这些承诺原样写入 `checks/product-commitments.json`：`codeRefs` 指向真实代码位置，`scenarioIds` 对应 `checks/product-acceptance.config.mjs` 中的 Playwright 场景；暂不实施的承诺必须保留真实状态或填写获批的 `waiver`，不得在交付前删除。

如果只是审 UI，Composition Kit 可以缩短为“当前结构 / 推荐结构 / 风险区块 / 组件替换 / 守门项”。审查结论一旦进入实现，必须补回 Acceptance commitments，不能只把自然语言建议当作已落实依据。

## 模板选择速查

| 页面/流程 | 优先模板 | 典型区块 |
|---|---|---|
| 内部后台列表 | 后台列表页 | 标题、筛选、结果摘要、DataTable、分页 |
| 高密度明细 | 明细数据工作台 | 工具栏、筛选、内部滚动表格、详情面板、固定分页 |
| 人工复核与决策 | 复核决策工作台 | 子视图、筛选、可选择结果、证据详情、批准/退回、分页 |
| 客户可见服务 | 客户门户 | 入口导航、任务首页、列表、详情、帮助恢复 |
| 宿主插件 | 宿主插件设置页 | 原生标题、设置组、设置行、状态、危险操作 |
| AI 输入/执行 | Agent 对话输入区 | 输入、控制行、Task Bar、审批、文件/上下文 |
| AI 输出/产物 | 助手输出文档流 | 用户消息、助手正文、过程、工具调用、产物 |
| 变更审批 | 变更审阅 / 同步冲突 | 风险摘要、文件列表、Diff 摘要、主动作、次动作 |

## 后台列表页

适用：运营后台、配置页、订单/线索/账户列表。

结构：

1. 页面标题区：唯一 H1、简短说明、页面主操作。
2. 筛选区：搜索、筛选、批量操作、清空/折叠。
3. 结果摘要：数量、实时/演示数据标记、当前筛选摘要。
4. 内容区：共享 DataTable 或移动端记录卡片。
5. 分页区：范围、每页条数、页码输入、前后翻页。

规则：

- 筛选、分页、排序应可恢复，必要时进入 URL。
- 表格 empty/loading/error 不能空白。
- 移动端不要强行展示宽表。
- 页面 H1 只出现一次，shell/topbar 不重复 H1。

## 明细数据工作台

适用：长表、订单明细、线索明细、对账明细。

桌面结构：

- 全宽工作区。
- 固定顶部导航或操作栏。
- 页面外层固定在视口内。
- 筛选区尽量单行或紧凑换行。
- 结果区内部滚动。
- 表头可 sticky，分页固定在结果区底部可见。

移动端结构：

- 回到自然页面滚动。
- 筛选可折叠。
- 记录卡片替代表格。
- 分页保留上一页、页码输入、下一页。

## 复核决策工作台

适用：异常记录复核、内容审核、变更审批、需要边看证据边作决定的运营任务。

结构：

1. `TertiaryNav`：切换稳定任务队列，不承载临时筛选条件。
2. `FilterBar`：集中关键词、状态和风险条件，并给出当前结果摘要。
3. 结果区：桌面使用可选择 `DataTable`；移动端以 `MobileRecordCard` 保留关键字段、状态、选择与详情动作。
4. 详情区：用 `DefinitionList` 呈现稳定字段，用普通正文呈现证据摘要。
5. 决策区：唯一 `ApprovalPanel` 承载批准、退回、提交中和完成状态。
6. `TablePagination`：桌面与移动端共享页码和总量状态。

规则：

- 结果列表和详情面板共享当前记录；移动端切换承载形式时不得重置选择。
- 批量动作只作用于明确选中的记录；没有选择时保持禁用。
- `ApprovalPanel` 只承载一次明确决策，不代替一般错误提示或普通页面操作。
- 决策完成后保留稳定结果与审计去向，不能只显示短暂 Toast。
- 窄屏回到自然页面滚动，先读记录，再进入详情和决策；不把桌面双栏等比缩小。

## 客户门户

适用：客户、经销商、合作伙伴可见的服务门户。

结构：

1. 入口导航：身份、当前角色、主要模块。
2. 任务首页：待处理事项、状态摘要、最近记录。
3. 列表页：筛选、状态、详情入口。
4. 详情页：当前状态、下一步动作、历史记录。
5. 帮助与错误恢复：权限不足、数据缺失、提交失败。

规则：

- 视觉强度可以高于内部后台，但仍以任务完成为核心。
- 关键状态要有明确下一步。
- 错误恢复要页面内可见，不能只用 toast。

## 宿主插件设置页

适用：Obsidian、VS Code、浏览器插件、企业平台内嵌设置。

结构：

1. 宿主原生标题。
2. 紧凑分区导航。
3. 设置组。
4. 设置行：名称、说明、控件、状态。
5. 危险操作放组尾。

规则：

- 优先使用宿主原生组件。
- 品牌只出现一次或作为小身份信号。
- 不要把设置页做成营销页或 dashboard。
- 状态反馈贴着相关设置，不散落成独立卡片。

## Agent 对话输入区

适用：AI 助手、自动化工具、任务编排。

结构：

1. 输入内容区。
2. 控制行：模型、权限、上下文、Skill、发送。
3. 附着区：Task Bar、文件选择、Skill 列表、审批强提醒。

状态：

- 未输入。
- 已输入。
- Skill 调用。
- 文件/上下文选择。
- Task Bar 收起。
- Task Bar 展开。
- 审批占用态。

规则：

- Task Bar 收起态贴住输入框上方，不占用输入内容区。
- 审批阻塞时作为输入区主状态，不在消息流重复强提醒。
- Skill 展示用技能名，不显示 `Skill /xxx`，除非是用户原始命令输入。

## 助手输出文档流

适用：AI 回答、长任务结果、工具调用记录。

结构：

- 用户消息：右侧气泡或宿主默认用户消息。
- 助手消息：文档流，不做与用户相同的大气泡。
- 身份行：助手身份 + 用时 + 展开入口。
- 正文：普通内容。
- 过程：默认收起或低强调。
- 工具调用：低强调事件行。
- 产物：文件行，带文件类型图标。

规则：

- 工具调用不是主阅读内容，不做重卡片。
- 过程步骤可展开，但不要再加“过程”标题。
- 已完成步骤可带一行自然语言小结。

## 变更审阅 / 同步冲突

适用：文件修改审批、Diff、同步冲突、本地/远端选择。

结构：

1. 风险摘要。
2. 文件列表，使用文件类型图标。
3. 关键 Diff 摘要。
4. 主动作：应用修改、采用本地、采用远端。
5. 次动作：查看完整 Diff、取消。

规则：

- 变更审阅是审批子系统，不另起强提醒样式。
- 操作文案必须说明采用哪一侧或会发生什么。
- 原始命令、snapshot 路径和长 diff 放详情，不放首屏。
