# Code Review Checklist

按以下顺序做最小必要审查，不需要每次全量展开。

## 1. 功能正确性

- 需求和实现是否一致
- 返回值、状态流转、分支条件是否正确
- 读写路径是否命中正确对象或正确数据源

## 2. 回归风险

- 原有调用方是否被新字段、新参数或新流程破坏
- 兼容路径是否仍然可走通
- 默认值、空值、旧数据是否还能正常处理

## 3. 边界与异常

- 空值、重复值、超长值、非法值是否处理
- 外部依赖失败时是否有降级或清晰报错
- 日志、异常和用户可见反馈是否一致

## 4. 数据与状态一致性

- 状态是否在多个对象间同步
- 事务边界、幂等性、重复提交是否考虑
- 缓存、聚合、异步结果是否可能脏读

## 5. 测试缺口

- 关键主路径是否有验证
- 新增分支是否缺测试
- 回归风险点是否有最小验证动作

## 6. 可维护性

- 职责是否明显漂移
- 是否引入难以维护的硬编码或重复逻辑
- 命名和结构是否已影响后续理解成本

## 严重度建议

- `High`：会导致错误结果、数据错乱、明显回归、关键流程不可用
- `Medium`：高概率埋雷、边界错误、明显漏测、维护风险较高
- `Low`：可读性或结构问题，短期不一定出错，但应尽快治理
