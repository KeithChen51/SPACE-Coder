# Code Review

本 skill 是 `project-manager-suite` 的代码审核能力。

它负责：

- 识别功能缺陷和行为回归
- 识别边界条件、异常路径和状态流转风险
- 识别模块耦合、职责漂移和可维护性问题
- 识别测试缺口、验收缺口和回归风险
- 输出按严重度排序的审查结论

它不负责：

- 直接替代开发完成所有修复
- 只做格式化或低价值风格挑刺
- 把“可以更优雅”误报成真实缺陷

## 触发条件

在以下情况优先使用本 skill：

- 用户明确说“review”“代码审核”“看下有没有问题”
- 需要在提交前做一次变更检查
- 需要从 bug、回归和测试覆盖视角审查某个模块
- 需要快速判断当前改动是否达到可合并质量

## 使用原则

1. 先读变更，再读必要上下文，不先泛读全仓。
2. 先找真实缺陷和回归风险，再考虑可维护性问题。
3. 结论必须给出“为什么是问题”和“影响范围”。
4. 没有证据支撑时，不把主观偏好写成缺陷。
5. 若涉及具体语言/框架规范，按需加载 `coding-standards`。

## 默认输入

优先读取：

- 当前 diff、目标文件或用户指定审查范围
- 当前执行计划中的相关任务和完成标准
- 相关 PRD、测试用例或验收标准（若存在）

必要时再读取：

- `references/review-checklist.md`
- `../coding-standards/SKILL.md`

## 默认工作流

### Step 1：确定审查范围

- 识别用户要审查的是 diff、单文件、模块还是整轮改动
- 确认是否有明确的完成标准、PRD 或缺陷背景
- 若范围过大，优先聚焦当前改动面

### Step 2：按风险主线审查

按以下顺序检查：

1. 功能正确性
2. 回归风险
3. 边界条件 / 异常处理
4. 状态与数据一致性
5. 测试缺口
6. 可维护性问题

### Step 3：输出审查结论

- 按严重度排序列出发现
- 每条结论包含：问题、原因、影响、建议动作
- 若未发现缺陷，明确说明“未发现实质性问题”，并指出剩余风险

## 最小输出物

- 审查结论（按严重度排序）
- 关键风险说明
- 测试 / 验证缺口
- 是否建议进入修复或可合并结论

## 输出要求

- findings first，不先写摘要
- 每条结论尽量落到具体文件或具体行为
- 优先写“会出错 / 会回归 / 会漏测”的问题
- 若无发现，直接写“未发现实质性问题”
