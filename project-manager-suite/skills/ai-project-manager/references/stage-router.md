# 阶段路由规则

根据项目画像判断当前最合适进入的阶段。

## 阶段定义

### S0 想法澄清

适用信号：

- 用户只有模糊想法
- 目标用户或核心问题不清楚
- 第一版功能边界不清楚

当前轮输出：

- 项目画像初稿
- 待确认问题清单

### S1 方案成型

适用信号：

- 核心目标已清楚
- 已能列出 1~3 个关键功能
- 需要把业务想法转成结构化方案

当前轮输出：

- 需求摘要
- 模块清单
- 第一版范围定义

### S2 研发拆解

适用信号：

- 已有较清楚方案
- 需要拆成页面、接口、数据、任务
- 需要进入 PRD 或计划编写

当前轮输出：

- 模块任务清单
- PRD / 计划入口建议
- 待研发确认项

### S3 开发执行

适用信号：

- 需求已有稳定边界
- 已明确先做哪个模块
- 可以进入编码、联调、测试

当前轮输出：

- 当前开发任务
- 相关 skill 路由
- 验证口径

### S4 验收收口

适用信号：

- 已有可运行结果
- 当前重点转为验证、补缺口、总结、回写

当前轮输出：

- 验收清单
- 遗留问题清单
- 日志 / 复盘建议

## 决策规则

1. 若多个阶段都可选，优先较早阶段。
2. 若缺失关键业务信息，不要跳过 `S0`。
3. 若用户明确要求“先给方案”，通常进入 `S1`。
4. 若用户已有完整材料并要求拆任务，通常进入 `S2`。
5. 若用户直接要求实现某模块，但上下文不足，先补最少上下文，再进入 `S2` 或 `S3`。
