## 1. 目的

本文件定义 `project-manager-suite` 的项目全局文件读写协议。

重点不是再解释“四类文件是什么”，而是明确：

1. 谁先读什么
2. 谁可以写什么
3. 什么时候创建默认文件
4. 什么时候必须回写
5. 如何避免 4 类文件互相串写

最小公共字段合同见：

- `global-files-minimum-shared-protocol.md`

---

## 2. 总体原则

### 2.1 先识别，再创建

- 先识别宿主项目已有权威文件
- 能映射现有文件时，不新建重复文件
- 只有无法映射时，才创建默认全局文件

### 2.2 先读规则，再读状态

默认读取顺序固定为：

1. 全局规则文件
2. 项目画像文件
3. 当前执行计划文件
4. 项目状态回写文件

### 2.3 只按职责回写

- 长期规则写入全局规则文件
- 项目当前快照写入项目画像文件
- 当前阶段任务写入当前执行计划文件
- 本轮推进结果写入项目状态回写文件

禁止把 4 类职责混写到同一个文件里。

### 2.4 能补最小载体，不补完整大文档

V1 的目标是保证闭环，不是一次生成最完整文档。

因此默认策略是：

- 缺规则文件时，补最小规则入口
- 缺项目画像时，补最小项目画像
- 缺计划文件时，补最小计划载体
- 缺状态文件时，补最小状态回写载体

## 3. 四类文件读写表

| 文件类型 | 默认文件名 | 主要读取者 | 主要写入者 | 创建时机 | 强制回写时机 |
|---|---|---|---|---|---|
| 全局规则文件 | `project-rules.md` | 主入口、全部子 skill | 主入口、项目维护者 | 宿主项目缺少规则入口时 | 规则发生长期变化时 |
| 项目画像文件 | `project-profile.md` | 主入口、需求/方案/计划类 skill | 主入口 | 项目启动且缺少画像时 | 项目目标、阶段、协作模式、入口信息或执行主体变化时 |
| 当前执行计划文件 | `execution-plan.md` | 主入口、计划/执行/验收类 skill | 主入口、计划类 skill | 进入拆解或执行阶段且缺少计划时 | 当前任务、下一步、完成标准发生变化时 |
| 项目状态回写文件 | `project-status.md` 或 `logs/` | 主入口、全部子 skill | 主入口、状态回写类 skill | 本轮结束后缺少状态载体时 | 每轮推进结束时 |

## 4. 每类文件的读写规则

本节只定义读写边界：

- 谁主要读取
- 谁主要写入
- 什么时候更新
- 哪些内容不能串写

每类文件“最少要有哪些字段”不在本文件重复展开，统一以最小公共协议为准：

- `global-files-minimum-shared-protocol.md`

### 4.1 全局规则文件

负责：

- 长期有效规则
- 权威入口约定
- 协作边界
- 交付件底线

可写入者：

- 主入口
- 项目维护者

不应写入：

- 当前阶段任务
- 本轮结果
- 临时待办事项

更新触发：

- 权威入口变化
- 长期协作规则变化
- 交付标准变化

### 4.2 项目画像文件

负责：

- 项目目标与范围快照
- 当前阶段
- 当前最适合进入的阶段
- 当前轮应输出的交付物
- 协作模式
- 当前执行主体 / 审核主体
- 项目入口与识别信息
- 关键待确认项

项目画像字段在读写协议中统一分为 3 类：

1. 用户确认字段
   - 优先来自用户明确确认、现有业务资料或宿主项目已成立事实
2. 系统推断字段
   - 优先由主入口从仓库、文件角色映射、已有材料和现有上下文中推断
3. 主入口判断回写字段
   - 由主入口基于当前上下文综合判断后写回，用于沉淀当前阶段判断与推进结论

可写入者：

- 主入口

受控补充写入者：

- 需求、方案、计划类 skill

条件：

- 只能补充和修正项目快照
- 入口、身份识别、阶段判断等运行时基线，应优先收敛到项目画像
- 不能把详细任务明细写进画像文件

主入口读取项目画像时，默认优先级固定为：

1. 项目基础判断与阶段判断
2. 协作模式、执行主体、审核主体
3. 入口与识别信息
4. 范围、优先级、已有资产
5. 待确认项

默认来源口径：

- 项目目标、业务目标、团队职责、时间要求等项目事实，优先读取用户确认字段
- 入口与识别信息、已有资产、最优先模块等运行线索，优先读取系统推断字段
- 当前阶段、当前最适合进入的阶段、当前轮应输出的交付物、当前任务执行主体 / 审核主体、待确认项，优先读取主入口判断回写字段

入口与识别信息包括：

- 规则入口文件
- 计划入口文件
- 最近状态入口
- PRD 总入口
- 身份识别方式
- 任务类型规则入口
- 最近状态定位口径

当项目画像已提供入口与识别信息时：

- 主入口应优先按画像层执行
- 不应重复从其它文件重新发明一套入口口径

当项目画像缺失入口与识别信息时：

- 允许退回规则层、计划层、状态层做角色映射
- 仍无法确认时写 `待确认`

读写约束：

- 用户确认字段除非用户明确修正或事实已被新资料推翻，否则不应被主入口静默改写
- 系统推断字段允许随角色映射和入口识别结果更新
- 主入口判断回写字段应在阶段变化、路由变化、执行主体变化时及时刷新

阶段判断相关字段使用约定：

- `当前阶段` 是已有输入
- `当前最适合进入的阶段` 是主入口综合判断后的更强信号

当两者冲突时：

- 主入口应先解释差异
- 再更新项目画像
- 不应静默覆盖原记录

更新触发：

- 项目启动
- 项目阶段变化
- 协作模式变化
- 第一版范围调整
- 入口与识别信息补齐或修正
- 当前轮交付物判断变化
- 当前任务执行主体 / 审核主体变化

写入项目画像时，推荐优先回写：

- 项目目标澄清结果
- 当前阶段变化
- 当前最适合进入的阶段
- 当前轮应输出的交付物
- `solo / 团队协作` 变化
- 团队成员与身份识别
- 入口与识别信息补齐结果
- 当前优先级变化
- 待确认项变化
- 当前任务执行主体 / 审核主体

不应写入：

- 详细任务明细
- 前置依赖明细
- 完整过程日志
- 本轮完整执行记录

### 4.3 当前执行计划文件

负责：

- 当前阶段任务
- 下一步动作
- 完成标准
- 前置依赖

可写入者：

- 主入口
- 计划类 skill

受控补充写入者：

- 执行类 skill
- 验收类 skill

条件：

- 只能更新当前阶段推进所需内容
- 不能把长期规则写进计划文件
- 不能把完整过程日志写进计划文件

更新触发：

- 进入任务拆解阶段
- 当前任务完成或变更
- 下一步优先级变化

### 4.4 项目状态回写文件

负责：

- 本轮动作
- 本轮产出
- 风险与阻塞
- 待确认项
- 下一步建议

可写入者：

- 主入口
- 状态回写类 skill
- 完成本轮工作的基础子 skill

条件：

- 记录本轮事实
- 不在此文件中重新定义项目规则或长期范围

更新触发：

- 任一轮有效推进结束后
- 任一轮验收、变更、收口结束后

## 4.5 字段读写优先级

为了遵守渐进式披露，主入口和子 skill 在读写全局文件时，应遵循统一字段优先级：

1. 先读取必填字段
2. 不足以判断时，再补读可选字段
3. 自动推断字段优先推断，不默认追问
4. 禁止混入字段不得通过“补充说明”写回当前文件

应用规则：

- 若必填字段足够支撑当前轮判断，不继续扩写文件
- 若可选字段缺失但不影响判断，不阻断推进
- 若自动推断字段无法确认，写 `待确认`，不强行追问到底
- 若信息明显属于另一类全局文件，必须写回对应文件，不得混写

对于项目画像，进一步适用：

- 启动级缺口优先补：身份识别方式、计划入口、状态入口、PRD 入口、任务类型规则入口
- 推进级缺口在进入子 skill 前补：当前阶段、当前最适合进入的阶段、当前轮应输出的交付物、当前任务执行主体 / 审核主体
- 画像完善级缺口只在影响当前判断时补：目标用户、主要问题、第一版范围、已有材料、优先级信息

## 5. 主入口默认读写流程

### Step 1：识别

- 先按职责识别宿主项目已有文件
- 对已有文件做角色映射

### Step 2：读取

- 按固定顺序读取 4 类文件
- 识别缺失信息与冲突信息
- 读取项目画像时，优先建立项目快照、协作判断、入口与识别信息基线

### Step 3：补齐

- 缺项目画像时补项目画像
- 项目画像缺字段时，先补启动级缺口，再补推进级缺口
- 缺计划时补最小计划载体
- 缺状态文件时补最小状态回写载体
- 缺规则入口时补最小规则入口

### Step 4：路由

- 基于读取结果判断当前阶段
- 决定进入哪个能力
- 路由时至少应使用项目画像中的“当前最适合进入的阶段 / 当前轮应输出的交付物 / 当前任务执行主体 / 当前任务审核主体 / 当前最大不确定项”

### Step 5：回写

- 把项目快照变化写回项目画像
- 把当前阶段任务写回执行计划
- 把本轮结果写回状态文件
- 若本轮补齐了入口与识别信息、阶段判断或执行主体，也应同轮写回项目画像

## 6. 默认模板来源

当宿主项目没有对应全局文件时，默认使用以下模板：

- 全局规则文件：`skills/ai-project-manager/assets/global-files/project-rules.md`
- 项目画像文件：`skills/ai-project-manager/assets/global-files/project-profile.md`
- 当前执行计划文件：`skills/ai-project-manager/assets/global-files/execution-plan.md`
- 项目状态回写文件：`skills/ai-project-manager/assets/global-files/project-status.md`

## 7. 子 skill 约束

后续所有子 skill 都应明确写出：

1. 依赖哪些全局文件
2. 读取哪些字段
3. 是否需要回写
4. 回写到哪一类文件

禁止：

- 直接绕过全局文件只在对话中沉淀长期上下文
- 把多个文件角色写成一个混合大文档
- 在公开版基础子 skill 中擅自新增新的全局文件类型
- 为了追求完整度，把可选字段和自动推断字段强行提升为用户必填项

---

## 8. 一句话结论

项目全局文件体系不是“文档集合”，而是 `project-manager-suite` 的默认路由骨架。
