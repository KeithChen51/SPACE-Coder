## 1. 目的

本文件定义 `project-manager-suite` 4 类项目全局文件的最小公共协议。

这里的“最小公共协议”专门回答：

1. 哪些字段是公开版和增强版都必须能识别的
2. 每类文件最少需要承载什么信息
3. 缺失时如何降级
4. 增强版扩展内容应落在哪一层，而不是破坏统一骨架

本文件是以下文档之间的中间合同：

- `global-files-model.md`
- `global-files-readwrite-protocol.md`
- `skills/ai-project-manager/assets/global-files/*.md`

一句话说：

**公开版和增强版可以在能力深度上分层，但必须共享同一套全局文件角色和最小字段合同。**

## 2. 总体约束

### 2.1 统一骨架

4 类全局文件角色固定为：

1. 全局规则文件
2. 项目画像文件
3. 当前执行计划文件
4. 项目状态回写文件

不允许因为版本差异新增第二套全局文件类型。

### 2.2 字段分层

每类文件中的字段统一分为：

- 必填字段
- 可选字段
- 自动推断字段
- 禁止混入字段

其中：

- 必填字段是最小公共协议的一部分
- 可选字段允许公开版缺失
- 自动推断字段优先从上下文推断
- 禁止混入字段不得写入当前文件

### 2.3 字段来源分类

除字段分层外，4 类全局文件中的字段在运行时还应统一按来源区分为：

1. 用户确认字段
   - 优先来自用户明确确认、现有业务资料或宿主项目已成立事实
2. 系统推断字段
   - 优先由主入口从仓库结构、已有文件、角色映射、运行结果和现有材料中推断
3. 主入口判断回写字段
   - 由主入口基于当前上下文综合判断后写回，用于沉淀阶段判断、推进结论和本轮状态

总体约束：

- 用户确认字段优先尊重用户原意，不应被主入口静默改写
- 系统推断字段优先自动补齐，无法确认时写 `待确认`
- 主入口判断回写字段必须允许随项目推进持续更新
- 若增强版或宿主项目增加额外字段，也应优先归入这 3 类之一，而不是新增第四种来源类型

### 2.4 兼容原则

必须满足：

1. 增强版写出的项目，公开版至少能识别并继续推进
2. 公开版初始化的项目，增强版可以直接接管
3. 版本差异不能要求迁移到另一套文件体系

### 2.5 降级原则

当某类文件缺失时：

- 先继续识别其余文件
- 再补最小默认载体
- 仍未知的信息写 `待确认`

不允许因为个别字段缺失而整体阻断项目启动。

## 3. 四类文件最小公共协议

## 3.1 全局规则文件

### 文件职责

回答：

- 这个项目怎么运行
- 哪些入口是权威源
- 哪些长期规则必须持续遵守

### 字段来源分类

全局规则文件默认以系统推断字段为主，必要时结合用户确认字段；主入口判断回写字段不应成为规则层主体。

字段级默认归属应理解为：

| 字段类型 | 默认字段 |
|---|---|
| 用户确认字段 | `协作边界` 中需要长期确认的上位口径、长期有效的业务协作原则 |
| 系统推断字段 | `规则权威文件`、`计划权威文件`、`状态回写权威文件`、`是否要求每轮沉淀交付物`、`其他关键入口`、`主要目录结构`、`关键文档目录`、`技术栈边界`、`关键代码目录`、`默认工作语言`、`默认沟通方式` |
| 主入口判断回写字段 | 仅限被正式升级为长期规则的新纪律或新约束，不作为规则层默认主体 |

默认约束：

- 单轮结论、单轮任务和本轮状态不应以主入口判断回写字段的名义直接写进规则层
- 只有满足长期稳定、跨轮次有效、可执行检查时，主入口结论才允许升级为规则层内容

### 必填字段

- 规则权威文件
- 计划权威文件
- 状态回写权威文件
- 是否要求每轮沉淀交付物

### 可选字段

- 其他关键入口
- 主要目录结构
- 关键文档目录
- 技术栈边界
- 协作边界
- 阶段最小交付件要求

### 自动推断字段

- 关键代码目录
- 默认工作语言
- 默认沟通方式

### 禁止混入字段

- 当前阶段任务清单
- 本轮风险与阻塞
- 单次需求细节
- 完整过程日志

### 缺失时降级策略

- 若宿主项目已有其它权威规则文件，可先做角色映射
- 若完全缺失，由主入口补最小 `project-rules.md`
- 技术边界未知时可暂写 `待确认`

### 兼容要求

- 增强版可增加更细的规则说明
- 但不能删掉 4 个必填字段所表达的最小入口语义

## 3.2 项目画像文件

### 文件职责

回答：

- 这个项目当前是什么
- 当前处在哪个阶段
- 当前由谁推进、谁确认

### 字段来源分类

字段级默认归属应理解为：

| 字段类型 | 默认字段 |
|---|---|
| 用户确认字段 | `项目名称`、`项目一句话目标`、`协作模式`、`第一版核心目标`、`目标用户`、`主要问题`、`第一版范围`、`其他成员`、`任务拆分方式` |
| 系统推断字段 | `身份识别口径`、`已有文档`、`已有原型 / 截图`、`已有系统 / Excel / 流程`、`最优先模块` |
| 主入口判断回写字段 | `当前阶段`、`当前最适合进入的阶段`、`当前轮应输出的交付物`、`当前任务执行主体`、`当前任务审核主体`、`当前最大不确定项` |

### 必填字段

- 项目名称
- 项目一句话目标
- 当前阶段
- 协作模式
- 第一版核心目标
- 当前最适合进入的阶段
- 当前轮应输出的交付物
- 当前任务执行主体
- 当前任务审核主体

其中默认分类为：

- 用户确认字段：`项目名称`、`项目一句话目标`、`协作模式`、`第一版核心目标`
- 主入口判断回写字段：`当前阶段`、`当前最适合进入的阶段`、`当前轮应输出的交付物`、`当前任务执行主体`、`当前任务审核主体`

### 可选字段

- 目标用户
- 主要问题
- 第一版范围
- 其他成员
- 任务拆分方式
- 当前最大不确定项

其中默认分类为：

- 用户确认字段：`目标用户`、`主要问题`、`第一版范围`、`其他成员`、`任务拆分方式`
- 主入口判断回写字段：`当前最大不确定项`

### 自动推断字段

- 身份识别口径
- 已有文档
- 已有原型 / 截图
- 已有系统 / Excel / 流程
- 最优先模块

这些字段默认归入系统推断字段。

说明：

- 上表是项目画像最小公共协议的默认字段归属总表
- `project-profile.md` 模板中若出现协议之外的扩展字段，也应按同一分类口径标注

### 禁止混入字段

- 长期规则定义
- 完整任务明细
- 开发过程日志
- 全量变更历史

### 缺失时降级策略

- 若无项目画像，主入口必须优先通过最小访谈补齐
- 无法确认的信息写 `待确认`
- 若阶段仍不明确，默认回到更靠前阶段

### 兼容要求

- 增强版可增加更细的角色、范围和判断字段
- 但必须保留“项目是什么、当前阶段是什么、由谁推进”这组最小语义

## 3.3 当前执行计划文件

### 文件职责

回答：

- 现在做什么
- 下一步做什么
- 什么算完成

### 字段来源分类

当前执行计划文件默认以主入口判断回写字段为主，必要时结合系统推断字段；用户确认字段不应成为计划层主体。

字段级默认归属应理解为：

| 字段类型 | 默认字段 |
|---|---|
| 用户确认字段 | 不作为计划层默认主体；若存在，多用于引用用户已确认的阶段目标或限制条件 |
| 系统推断字段 | `部分前置依赖`、`任务优先级`、`可并行任务`，以及部分由上下文可恢复的依赖关系 |
| 主入口判断回写字段 | `当前阶段`、`当前目标`、`进行中任务`、`下一步任务`、`完成标准`、`前置依赖`、`待确认项`、`当前阶段里程碑`、`任务执行顺序` |

默认约束：

- 计划层优先回答“现在做什么、下一步做什么、什么算完成”
- 即使某些目标或约束源自用户确认，也应先由主入口转写成当前轮可执行计划，再落入计划层
- 若某项内容仍停留在项目事实描述而未形成当前轮执行语义，不应提前写入计划层

### 必填字段

- 当前阶段
- 当前目标
- 进行中任务
- 下一步任务
- 完成标准

### 可选字段

- 前置依赖
- 待确认项
- 当前阶段里程碑
- 任务执行顺序

### 自动推断字段

- 部分前置依赖
- 任务优先级
- 可并行任务

### 禁止混入字段

- 项目长期规则
- 团队基础画像
- 完整开发日志
- 长期决策档案

### 缺失时降级策略

- 若尚未进入拆解或执行阶段，可先只依赖项目画像推进
- 一旦进入拆解或执行阶段，应补最小 `execution-plan.md`
- 若任务尚不明确，可先只写“当前目标 + 下一步任务 + 完成标准”

### 兼容要求

- 增强版可增加更细任务结构、优先级和依赖
- 但必须保留“当前做什么、下一步做什么、什么算完成”这组最小语义

## 3.4 项目状态回写文件

### 文件职责

回答：

- 最近发生了什么
- 本轮产出了什么
- 当前卡在哪里

### 字段来源分类

项目状态回写文件默认以主入口判断回写字段为主，必要时结合系统推断字段；用户确认字段不应成为状态层主体。

字段级默认归属应理解为：

| 字段类型 | 默认字段 |
|---|---|
| 用户确认字段 | 不作为状态层默认主体；若存在，多体现为本轮确认结论被记录进状态 |
| 系统推断字段 | `本轮时间`、`本轮涉及文件`、`本轮关联阶段`、`本轮执行主体` |
| 主入口判断回写字段 | `本轮动作`、`本轮产出`、`当前结论`、`下一步建议`、`风险与阻塞`、`待确认项`、`本轮决策`、`本轮验收结论` |

默认约束：

- 状态层优先记录本轮事实和本轮结论
- 不应要求用户手工维护整份状态文件
- 即使部分结论来自用户确认，也应先由主入口或状态回写类能力整理成“本轮发生了什么”的状态表达，再写入状态层

### 必填字段

- 本轮时间
- 本轮动作
- 本轮产出
- 当前结论
- 下一步建议

### 可选字段

- 风险与阻塞
- 待确认项
- 本轮决策
- 本轮验收结论

### 自动推断字段

- 本轮涉及文件
- 本轮关联阶段
- 本轮执行主体

### 禁止混入字段

- 项目基础画像定义
- 长期规则定义
- 全量任务计划
- 与本轮无关的大段背景说明

### 缺失时降级策略

- 若状态文件缺失，不阻断当前轮推进
- 但本轮结束前应补最小 `project-status.md`
- 若暂无完整结论，至少记录“本轮动作 + 本轮产出 + 下一步建议”

### 兼容要求

- 增强版可增加更细的变更、验收、风险结构
- 但必须保留“最近做了什么、产出了什么、下一步是什么”这组最小语义

## 4. 主入口读取目标

`ai-project-manager` 每次重新进入项目时，至少应能从统一骨架中恢复以下最小信息：

1. 项目规则入口是什么
2. 项目当前是什么
3. 当前阶段是什么
4. 当前正在做什么
5. 最近发生了什么
6. 下一步是什么

本节只定义“主入口至少要能恢复什么信息”，不定义读取顺序、创建时机和回写时机。

具体流程见：

- `global-files-readwrite-protocol.md`

---

## 5. 模板对齐要求

4 个默认模板至少应覆盖各自文件的必填字段。

若模板中存在以下问题，应视为与最小公共协议不一致：

- 缺失必填字段
- 把禁止混入字段写进默认模板
- 把可选字段或自动推断字段提升为用户强制输入

---

## 6. 子 skill 字段对齐要求

所有基础子 skill 和增强子 skill 后续都应明确：

1. 依赖哪一类全局文件
2. 至少读取哪些必填字段
3. 会补充哪些可选字段
4. 回写哪一类全局文件
5. 不得把哪类信息串写到错误文件

若一个 skill 无法回答以上问题，则说明它尚未对齐统一项目骨架。

具体写入者、回写触发时机和读写顺序见：

- `global-files-readwrite-protocol.md`

---

## 7. 一句话结论

`project-manager-suite` 的 4 类全局文件不是普通模板集合，而是公开版和增强版共享的项目级持久化上下文合同。
