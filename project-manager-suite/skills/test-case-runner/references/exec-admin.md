# 管理台闭环用例执行规则

> 本文件在每条管理台闭环用例开始执行前读取。
> 管理台闭环测试的核心是**验证"管理员通过界面操作 → C 端用户看到变化"这条完整链路**。

## 执行流程

1. **读取用例文档步骤** — 打开用例详情文档，找到当前编号对应的"步骤"和"预期结果"，**逐步照做**。文档写了几步就执行几步，不跳步、不合并、不替代。

2. **设置桌面视口** — 管理台是桌面端应用，必须先恢复桌面尺寸：
   ```
   browser_resize: { width: 1440, height: 900 }
   ```
   如果之前跑 C 端 UI 用例时设了手机视口（375×812），不切回来会导致管理台页面布局全部变形。

3. **管理台操作（必须人类可见）** — 导航到 `${ADMIN_URL}` 对应页面，**像真实管理员一样通过界面操作**完成配置修改；执行时必须使用人类可见的浏览器窗口，让协作中的人类可以同步看到当前页面：
   - 用 `browser_snapshot` 获取页面元素 ref
   - 用 `browser_click`、`browser_fill_form` 等操作界面
   - 文档说"点击保存"就在 UI 上点击保存按钮
   - 每个关键操作后截图取证
   - **凡涉及按钮操作（保存/刷新/搜索/提交/触发同步/打开弹窗等）**，都必须额外留存一张包含操作结果弹窗或 toast 的截图；若按钮点击后按预期本就不会出现弹窗，也必须在报告中明确写“未出现弹窗，属页面设计如此”，不能留空
   - **凡涉及二次确认的按钮操作（删除/确认提交/覆盖配置/执行同步等）**，必须留存两张独立证据图：一张截“确认弹窗”，一张截“确认后的结果 toast/结果弹窗”。不能只留后一拍结果图来替代完整过程证据

4. **C 端验证** — 管理台操作完成后，验证 C 端是否生效：
   - 用 curl 调 C 端 API 验证数据变化
   - 或用浏览器打开 C 端页面验证（需切回手机视口 375×812）

5. **截图取证** — **管理台和 C 端各截图一张**，保存到：
   ```
   docs/test-case/reports/{git用户名}/screenshots/{区块名}/
   ```
   - 如果该条用例包含按钮操作，则上述“管理台截图”不能只留整页状态图，必须至少包含一张“按钮操作结果弹窗 / toast”截图
   - 如果该条用例包含二次确认操作，则截图清单必须显式包含：`确认弹窗图`、`确认后结果图`；缺任一张都要在报告中标注“证据不完整，需补采”

6. **数据还原** — 按用例文档的"数据清理"段执行还原。如果清理方式是"管理台还原为基线值"，则**必须通过管理台 UI 操作还原**，不能用 SQL 直改。

## 严禁绕过界面

这是管理台闭环测试的铁律，没有任何例外：

- **严禁仅用无头/后台浏览器完成整条闭环**，如果人类看不到当前执行页面，不得直接据此宣称管理台 UI 用例通过
- **严禁用 SQL 直接改数据库**来替代管理台 UI 操作
- **严禁用 curl 直接调后端 API**来替代管理台 UI 操作
- **严禁用 `browser_run_code`/`page.evaluate()`** 来执行 JS 替代用户点击

如果管理台界面操作未能生效（比如点击保存后数据库没变化），**这就是一个 BUG，必须判 FAIL 并记录缺陷**。

测试验证的是用户操作路径，不是接口能力。如果界面显示"保存成功"但实际没保存，这正是测试需要发现的问题。

## FAIL vs BLOCKED 判定

| 情况 | 判定 | 理由 |
|------|------|------|
| 功能入口/配置区域不存在 | **FAIL** | 功能缺失是产品缺陷，不是外部阻塞 |
| 页面能打开但操作失败（保存不生效、输入框不可编辑等） | **FAIL** | UI 功能异常是 BUG |
| 管理台整站不可访问（服务器宕机、网络不通） | **BLOCKED** | 外部环境问题，非产品缺陷 |
| 前置用例的产出数据缺失导致无法继续 | **BLOCKED** | 真依赖阻塞 |

**核心原则**：只有**外部环境不可用**才是 BLOCKED；**功能没做、功能有 BUG** 都是 FAIL。

### 典型违规场景

| 违规操作 | 正确做法 |
|---------|---------|
| 管理台保存按钮失效 → 改用 `curl PUT` 让数据生效 → 宣称 PASS | 判 FAIL，记录缺陷 |
| 管理台功能入口不存在 → 标为 BLOCKED → 跳过 | 判 FAIL，记录"功能缺失"缺陷 |
| 管理台输入框无法编辑 → 用 `page.evaluate()` 直接设值 → 继续 | 判 FAIL，记录缺陷 |
| 管理台整站宕机无法访问 → 改用 SQL 直改 DB | 判 BLOCKED，报告环境不可用 |
