# 反模板规则

本文件部分吸收 `taste-skill` 的反模板设计纪律，但只保留适合部门通用 skill 的规则。

## 先读场景

不要默认套用：

- 紫蓝渐变。
- 黑底发光 hero。
- 三个等宽功能卡片。
- 所有内容居中。
- 过度玻璃拟态。
- 大圆角泡泡风。
- 只有成功态的静态 UI。

先判断：

- 这是后台、报表、营销页还是产品界面？
- 用户是高频操作，还是低频浏览？
- 页面需要数据密度，还是品牌表达？
- 是否已经有品牌资产？

## 主题一致性

- 一个页面只用一个主视觉主题。
- 不要上一屏深色、下一屏浅色、再下一屏渐变，除非有明确叙事。
- 一个项目只用一个圆角系统。
- 一个项目只用一个图标风格。

## 颜色纪律

- 默认最多一个主强调色。
- 状态色只表达状态，不承担装饰。
- 不要把所有图标和标题都染成主色。
- 不要使用随机渐变作为默认 CTA。
- 对外页面如需强视觉，要先解释为什么这种颜色适合业务。

## 布局纪律

- 后台和数据产品优先信息扫描，不要做营销页 hero。
- 长表格不套大卡片堆叠。
- 页面区块不要卡片套卡片。
- 高密度页面优先用分隔线、表头、留白，不靠阴影堆层级。
- 移动端要明确折叠规则，不能只依赖桌面布局缩放。

## 内容纪律

- 不使用“Jane Doe / Acme / Lorem Ipsum”作为最终示例。
- 按钮文案要具体。
- 空状态要说明下一步。
- 错误文案要给修复路径。
- 不写“专为 X 打造”这类泛化营销句，除非用户明确要做营销页。

## 视觉资产

- 需要真实产品、真实状态或真实截图时，不要用纯装饰 SVG 假装。
- 如果没有资产，使用明确的占位策略，并告诉用户需要什么素材。
- 不重新绘制、重配色或生成已有品牌 Logo。

## 最终自检

交付前检查：

- 是否声明了设计读取？
- 是否选择了 default/customize/design-system/review 主模式，并单独判断 preview_decision？
- 是否避免了模板化三卡片、紫色渐变、居中堆叠？
- 是否有 loading/empty/error 状态？
- 是否通过按钮对比度、文本换行和移动端检查？
