# 单元测试与自动化测试规范

> 来源：阿里巴巴 Java 开发手册 §3 单元测试 + 通用工程测试实践
> 适用：编写 Java 单元测试、前端自动化测试、组件测试
> 边界说明：测试用例文档设计、编号、验收矩阵、缺陷回归规则见 `11-test-case-design.md`

---

## 基本原则

1. 【强制】遵循 **AIR 原则**：
   - **A**utomatic：全自动执行，非交互式
   - **I**ndependent：用例之间不互相调用、不依赖执行顺序
   - **R**epeatable：不受外界环境影响，可重复运行
2. 【强制】遵循 **BCDE 原则**：
   - **B**order：边界值测试（空值、极大值、零值）
   - **C**orrect：正确输入 -> 预期结果
   - **D**esign：与 PRD / 设计文档结合
   - **E**rror：异常输入 -> 预期错误处理

## 测试编写

3. 【强制】测试代码必须与业务代码分目录管理，禁止混入正式代码目录。
4. 【强制】测试类命名：被测类名 + `Test`，如 `OrderServiceTest`。
5. 【强制】必须使用断言验证，禁止 `System.out.println` 人肉验证。
6. 【强制】测试粒度为方法级或行为级，一个测试方法只验证一个核心逻辑点。

## 覆盖率

7. 【推荐】语句覆盖率目标 **70%+**。
8. 【推荐】核心模块（Service 层、工具类、关键状态机）语句覆盖率和分支覆盖率尽量达到 **100%**。
9. 【强制】核心业务的增量代码必须补充自动化测试。

## 数据相关测试

10. 【推荐】不假设数据库或外部存储中已有数据，用脚本、工厂方法或 mock 准备测试数据。
11. 【推荐】测试执行后自动回滚或清理数据，不留脏数据。
12. 【推荐】测试数据使用明确前缀标识，如 `TEST_`、`MOCK_`。

## 常见测试命令

以下命令仅为常见示例，迁移到具体项目后应替换为项目真实命令：

```bash
# Java 后端测试
mvn test

# Node / 前端单元测试
npm run test

# 构建验证
npm run build
```

## 前端自动化测试

13. 【推荐】组件测试覆盖 Props 渲染、事件触发、条件展示和空态。
14. 【推荐】Composable / Hooks 编写独立单元测试。
15. 【推荐】测试文件放 `__tests__/` 或与组件同目录，命名 `Xxx.test.js`、`Xxx.test.ts`。
