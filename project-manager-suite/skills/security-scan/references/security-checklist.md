# Security Scan Checklist

优先检查高风险攻击面，不需要每次全量展开所有条目。

## 1. 认证与授权

- 是否缺登录校验
- 是否存在普通用户访问管理员能力
- 是否只校验“已登录”而未校验“是否有权限”
- 是否存在对象级越权（A 能读写 B 的资源）

## 2. 输入校验与注入

- SQL、命令、模板、脚本、路径拼接是否安全
- 查询参数、表单参数、Header、Cookie 是否做最小必要校验
- 是否直接信任前端传入的标识、状态或角色

## 3. 敏感数据与秘密信息

- 代码、日志、配置中是否暴露密钥、令牌、密码
- 敏感字段是否明文返回给前端
- 错误信息是否泄露内部路径、SQL、堆栈或环境信息

## 4. 文件上传 / 下载

- 是否校验文件类型、大小、扩展名
- 是否存在路径穿越、任意文件读取或覆盖
- 下载接口是否校验资源归属和权限

## 5. 外部调用

- 是否存在可控 URL 请求导致 SSRF
- 是否存在开放重定向
- Webhook、回调、第三方同步是否校验来源和签名

## 6. 前端安全

- 输出内容是否缺少转义导致 XSS
- 危险 HTML 渲染是否受控
- 状态变更接口是否需要 CSRF 防护或等价防护

## 7. 配置与部署

- 默认账号、默认密码、调试开关是否暴露
- CORS、跨域、上传目录、公开目录是否放得过宽
- 日志和监控是否把敏感信息打出

## 风险等级建议

- `Critical`：可直接导致未授权控制、批量泄露、远程执行或严重资金风险
- `High`：可稳定利用，影响核心数据、核心接口或后台权限
- `Medium`：需要一定前提，影响局部功能或敏感数据
- `Low`：安全治理问题，短期不一定直接被利用，但应修复
