# Security Scan

本 skill 是 `project-manager-suite` 的安全审查能力。

它负责：

- 识别鉴权、越权、注入、上传、反序列化等常见安全风险
- 识别敏感信息暴露、密钥泄露和配置风险
- 识别输入校验缺失、输出转义缺失和危险默认配置
- 输出按风险等级排序的安全问题和修复建议

它不负责：

- 伪装成真实渗透测试执行外部攻击
- 在没有证据时夸大安全结论
- 代替专门的 SAST / DAST 工具报告所有细节

## 触发条件

在以下情况优先使用本 skill：

- 用户明确要求“安全扫描”“安全审查”“漏洞检查”
- 涉及登录、权限、接口开放、文件上传、支付、后台配置等高风险功能
- 提交前需要做一次快速应用安全把关
- 发布前需要确认当前改动是否引入明显攻击面

## 使用原则

1. 先看攻击面，再看代码细节，不先做机械全量罗列。
2. 先报可利用、高影响的问题，再报治理类问题。
3. 每个风险都要说明攻击路径或利用前提。
4. 若只是“需要进一步验证”，明确写成待验证，不伪装成确定漏洞。
5. 涉及具体实现规范时，按需加载 `coding-standards`。

## 默认输入

优先读取：

- 当前 diff、目标接口、目标模块或用户指定范围
- 与认证鉴权、输入输出、上传下载、外部调用相关的代码
- 当前项目规则中的安全边界或发布边界（若存在）

必要时再读取：

- `references/security-checklist.md`
- `../coding-standards/SKILL.md`

## 默认工作流

### Step 1：确定扫描范围与攻击面

- 识别当前改动是否涉及接口、页面、后台、任务脚本或配置
- 识别是否有新增攻击面：新接口、新参数、新上传、新外部调用、新权限入口
- 若范围过大，先聚焦本轮改动和外部可触达入口

### Step 2：按高风险路径扫描

优先检查：

1. 认证与授权
2. 输入校验与注入
3. 敏感数据与秘密信息
4. 文件上传 / 下载
5. 外部请求与 SSRF / 重定向
6. 前端输出与 XSS / CSRF
7. 危险配置与默认值

### Step 3：输出安全结论

- 按 `Critical / High / Medium / Low` 排序输出
- 说明利用前提、影响范围、修复建议
- 若未发现高风险漏洞，明确说明剩余盲区和建议补充验证动作

## 最小输出物

- 安全问题清单（按风险等级排序）
- 利用前提与影响说明
- 修复建议
- 剩余盲区 / 建议补充验证动作

## 输出要求

- 先写高风险问题，再写次级风险
- 每条问题说明“攻击者如何利用”
- 不把纯代码洁癖写成安全漏洞
- 无高风险时明确写“未发现明显高风险漏洞”
