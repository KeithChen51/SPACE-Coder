# Delivery Planner

本 skill 是 `project-manager-suite` 的默认计划拆解能力。

它负责：

- 将模块和方案拆解为可执行任务
- 明确任务执行顺序和依赖关系
- 定义每项任务的完成标准
- 确认执行主体和审核主体

它不负责：

- 需求澄清和方案设计
- 具体编码实现
- 测试执行和验收
- 高级排期和资源调度

## 触发条件

在以下情况优先使用本 skill：

- 需求范围已稳定，基础方案已成型
- 主入口判断当前阶段为 S2（研发拆解）
- 用户明确要求"拆任务""排计划""做执行计划"
- 当前任务执行主体和审核主体已足以支撑拆解

## 使用原则

1. 任务粒度应适合单次执行，不宜过大或过碎。
2. 每项任务必须有明确的完成标准。
3. 没有执行主体的任务不能视为有效拆分。
4. 先拆核心路径，再补充周边任务。
5. 区分前置依赖和可并行的任务。

## 默认输入

优先读取：

- 页面确认后的完整 PRD（`prd-writer` 产出）
- 项目画像中的协作模式、执行主体、审核主体
- 当前执行计划中已有的阶段描述

必要时再读取：

- 全局规则文件中的协作边界和交付要求

## 读取的全局文件

- 项目画像文件：读取协作模式、执行主体、审核主体、第一版范围、当前优先级
- 全局规则文件：读取协作边界、交付件底线
- 当前执行计划文件：读取已有阶段计划
- 项目状态回写文件：读取最近推进状态

## 默认工作流

### Step 1：读取方案与协作上下文

- 吸收模块清单、范围边界、优先级
- 确认协作模式和执行主体

### Step 2：拆解为任务清单

- 按模块和优先级拆解为具体任务
- 标注前置依赖和执行顺序
- 为每项任务定义完成标准
- 为每项任务分配执行主体

### Step 3：输出执行计划

- 产出阶段化任务清单
- 写入或更新执行计划文件
- 标注待确认项

## 最小输出物

- 任务清单（含任务名、执行主体、完成标准、前置依赖）
- 执行顺序建议
- 待确认项

## 回写规则

- 回写到当前执行计划文件：当前阶段任务、下一步任务、完成标准、执行主体
- 回写到项目画像文件：当前阶段变化、当前任务执行主体变化
- 不得回写：长期规则定义、完整过程日志

## 输出要求

- 任务描述应具体可执行
- 完成标准应可验证
- 面向执行时结构化表达，标注执行主体和前置依赖

## 资源入口

暂无独立 references，后续按需补充。

## V1 边界

本 V1 先解决：

- 从方案生成基础任务清单
- 定义执行顺序和完成标准
- 让后续开发执行有稳定输入

本 V1 暂不解决：

- 复杂多团队排期协调
- 自动化工时估算
- 里程碑管理和甘特图
