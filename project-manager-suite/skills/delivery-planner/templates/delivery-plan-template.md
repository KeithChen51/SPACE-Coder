## 0. 本计划使用指南

### 0.1 AI 执行工作流（每个任务必须按此顺序）

```text
1. 读任务的「核心逻辑」
2. 读任务的「PRD 双链·读」
3. 读任务的「核心文件」
4. 完成读前门禁自检
5. 执行任务
6. 完成真实验证
7. 对照「完成标准」自验
8. 回写任务状态与日期
```

### 0.2 PRD 加载约束

1. 第一层：读取需求导航文档 / PRD 主文档
2. 第二层：按任务的 `PRD 双链·读` 读取相关章节
3. 第三层：跨域问题按需补读，不一次性拉入全部 PRD

**硬禁令**：
- 禁止一次性读取整个 PRD 目录
- 禁止读取与当前任务无关的 PRD 全文
- 大文件按章节号定位读取

### 0.3 读前门禁（AI 自检清单）

在动手前，AI 必须能回答：

| # | 问题 | 答案来源 |
|---|------|----------|
| 1 | 这项任务要实现哪条业务规则？ | `核心逻辑` |
| 2 | 前端应该展示什么，不应该做什么判断？ | PRD `前端职责` |
| 3 | 服务端如何计算或聚合？ | PRD `服务端处理逻辑` |
| 4 | 数据来自哪张表、哪个字段？ | PRD `数据链路表` |
| 5 | 异常时如何兜底？ | PRD `异常与兜底` |
| 6 | 配置面能改什么、不能改什么？ | PRD `配置约束` |

### 0.4 完成前验证门禁

#### A. 服务端任务
- 至少一次真实接口调用，核对 `code / message / data`
- 至少一次真实查询或真实保存回查
- 至少一次字段与表结构 / 映射核对

#### B. 前端任务
- 至少一次真实页面加载
- 至少一次异常态或失败态验证
- 涉及保存时，至少一次真实保存 -> 刷新/回读 -> 回显一致

#### C. 数据库任务
- 至少一次目标库结构 / 行数 / 关键字段验收
- 至少一次与下游接口或页面的真实可用性验证

#### D. 不足以判定完成的证据
- `npm run build` 通过
- 局部单测通过
- 页面能打开
- SQL 执行成功
- 代码看起来符合 PRD
