# Solution Designer

本 skill 是 `project-manager-suite` 的默认方案整理能力。

它负责：

- 把需求摘要转化为模块结构
- 明确第一版范围边界
- 输出可继续拆解的基础方案

它不负责：

- 详细技术架构设计
- 数据库表结构设计
- 任务拆解和排期
- 高保真原型设计

## 触发条件

在以下情况优先使用本 skill：

- 需求范围已基本可表达
- 主入口判断当前阶段为 S1（方案成型）
- 用户明确要求"整理方案""做模块设计""把需求变成方案"

## 使用原则

1. 先吸收需求摘要和项目画像，再补最少方案缺口。
2. 优先模块化思维，把功能归类为可独立推进的模块。
3. 明确第一版做什么、不做什么。
4. 方案粒度适中：比需求摘要更结构化，但不深入到代码级设计。
5. 对业务团队使用模块和功能语言，不使用纯技术术语。

## 默认输入

优先读取：

- 需求摘要（`requirements-starter` 产出）
- 项目画像中的项目目标、第一版范围、优先级
- 当前执行计划中的相关阶段描述

必要时再读取：

- 全局规则文件中的技术边界约束

## 读取的全局文件

- 项目画像文件：读取项目目标、第一版范围、当前优先级、待确认项
- 全局规则文件：读取技术栈边界、协作边界
- 当前执行计划文件：读取当前阶段目标
- 项目状态回写文件：不依赖

## 默认工作流

### Step 1：读取需求与上下文

- 吸收需求摘要中的业务目标、核心问题、第一版范围
- 识别已有技术边界和约束

### Step 2：整理模块结构

- 将功能点归类为模块
- 明确模块间依赖关系
- 标注第一版包含和不包含的模块

### Step 3：输出基础方案

- 产出模块清单 + 范围边界 + 模块优先级
- 标注待确认项和假设
- 建议下一步是否进入任务拆解

## 最小输出物

- 模块清单（含模块名称、职责、优先级）
- 第一版范围边界（做 / 不做）
- 待确认项

## 回写规则

- 回写到项目画像文件：第一版范围调整、待确认项变化
- 不得回写：详细任务明细、完整过程日志

## 输出要求

- 面向业务团队时，用模块和功能语言
- 面向后续拆解时，输出结构化模块列表
- 显式标注 `已知 / 假设 / 待确认`

## 资源入口

暂无独立 references，后续按需补充。

## V1 边界

本 V1 先解决：

- 从需求摘要生成基础模块清单
- 明确第一版范围边界
- 让后续任务拆解有稳定输入

本 V1 暂不解决：

- 详细技术架构文档
- 数据模型设计
- 复杂系统集成方案
