# 管理台配置测试 — 生成策略 + 模板

> 管理台配置测试针对**管理台本身的 CRUD 与配置生效流程**。
> 业务域型 TC（含"管理台改配置 → C 端生效"闭环）见 `type-domain.md` §6；本文件只覆盖独立的管理台 CRUD 文件。

## 1. 生成策略

- 按**配置页面**分组，一个配置页面一个测试文件
- 每组用例覆盖三类验证：**CRUD** 操作 → **配置生效** 验证 → **边界校验**
- 执行方式：浏览器 UI + 数据库查询 / API 抽检
- 预期结果**只来自验收文档条目**；数据库 / API 只用于"判定配置是否落库、是否生效"，不作为预期 oracle
- 不假设任何固定管理台 URL、接口路径、配置表名——全部占位符化，由宿主项目实际情况填入

## 2. 输入来源

| 输入 | 来源 | 用途 |
|------|------|------|
| 管理台相关验收条目 | `acceptance-<slug>/<区块名>.md` | 预期行为定义 |
| 配置表与字段 | `foundation-schema-<slug>` | 数据库层判定依据 |
| 管理台 API 契约 | `foundation-api-<slug>` 或宿主代码 | 保存成功判定、抽检调用 |

验收文档中需要特别关注两类条目：
- **管理台 CRUD**：新增 / 编辑 / 删除 / 列表查询一条配置项——本文件主要覆盖这类
- **管理台闭环**：改某个可编辑配置项 → C 端字段或行为生效——通常进业务域 TC 文件的第三组（见 `type-domain.md` §6），本文件不重复覆盖

## 4. 用例模板

```markdown
### {PREFIX}-{NN}：{用例标题}

> 验收文档：`acceptance-<slug>/<区块名>.md` §<X> 条目 {验收文档条目ID}
> 目标：验证 {配置操作的正确性与生效}
> 执行方式：浏览器 UI + 数据库 / API 抽检

**前提条件**：
- 管理台前端已启动
- {当前配置状态（人类可读描述）}

**数据准备**：
> 执行 [sql/{PREFIX}-{NN}.sql](sql/{PREFIX}-{NN}.sql) 中的"数据准备"段
> 或通过管理台 API 初始化：`POST {管理台URL}/admin/api/{配置接口}`

**步骤**：
1. 打开管理台 `{管理台URL}`，进入 `{配置页面}`
2. {操作：新增 / 编辑 / 删除 配置项}
3. 点击保存
4. 数据库判定：`SELECT * FROM {配置表} WHERE {字段}=...`

**预期结果**：

| 检查项 | 预期 |
|:---|:---|
| 前端提示 | 保存成功提示（依验收条目定义） |
| {配置表}.{字段} | 目标值（依验收条目定义） |
| 列表页展示 | 配置生效后的展示（依验收条目定义） |

**数据清理**：
> 执行 [sql/{PREFIX}-{NN}.sql](sql/{PREFIX}-{NN}.sql) 中的"数据清理"段
> 或通过管理台还原配置到前置状态
```

## 5. 数据准备与数据清理规则

- 初始状态优先**管理台 API 构造**，次选 SQL——避免绕过管理台校验直接写库导致基线失真
- 数据清理必须把配置还原到测试前状态；每条用例自包含
- 边界校验类用例（长字符串、非法字符、枚举外值）若已被表单拒绝，无需完整数据清理，但需记录"表单拒绝"事实
- 禁止用 `DELETE FROM {配置表}` 全表破坏性清理；用 `UPDATE ... SET isActive=0` 或定向 `DELETE WHERE {字段}=...` 指定行
