# Engineering Executor

本 skill 是 `project-manager-suite` 的默认开发执行能力。

它负责：

- 按计划推进当前开发任务
- 确保任务输出符合完成标准
- 在执行过程中记录关键决策和变更
- 执行完成后触发状态回写

它不负责：

- 需求澄清和方案设计
- 任务拆解和排期
- 测试验收和质量评审
- 定义项目长期规则

## 触发条件

在以下情况优先使用本 skill：

- 当前任务清晰，完成标准已定义
- 执行主体已明确
- 主入口判断当前阶段为 S3（开发执行）
- 用户明确要求"开始开发""实现这个功能""按计划执行"

## 使用原则

1. 先读计划再动手，确认当前任务和完成标准。
2. 涉及代码变更时，必须同时加载 `coding-standards` 能力。
3. 遇到计划外的问题或范围变化，先记录再继续，不擅自扩大范围。
4. 任务完成后触发状态回写，不跳过记录。
5. 阶段性产出应可验证，不以"做了一些工作"替代具体交付。

## 默认输入

优先读取：

- 当前执行计划中的进行中任务、完成标准、前置依赖
- 项目画像中的当前任务执行主体
- 任务关联的 PRD 或依据资料

必要时再读取：

- 全局规则文件中的技术边界和协作约束
- `coding-standards` 能力中的对应规范

## 读取的全局文件

- 当前执行计划文件：读取进行中任务、完成标准、前置依赖、PRD 依据
- 项目画像文件：读取当前执行主体、当前阶段
- 全局规则文件：读取技术栈边界、协作边界
- 项目状态回写文件：读取最近推进状态，避免重复工作

## 默认工作流

### Step 1：确认当前任务

- 从执行计划中读取当前进行中任务
- 确认完成标准和前置依赖
- 按计划补读任务所需依据资料

### Step 2：执行任务

- 按完成标准推进当前任务
- 涉及代码变更时加载对应 `coding-standards` 规范
- 遇到阻塞或范围变化时记录并反馈

### Step 3：完成并回写

- 确认任务输出是否符合完成标准
- 更新执行计划中的任务状态
- 触发状态回写

## 最小输出物

- 当前任务的执行结果
- 任务状态更新（完成 / 阻塞 / 需确认）
- 遇到的问题和决策记录

## 回写规则

- 回写到当前执行计划文件：任务状态变更、下一步任务
- 回写到项目状态回写文件：本轮动作、本轮产出、遇到的问题
- 不得回写：项目长期规则、项目基础画像（除非执行主体变化）

## 输出要求

- 执行结果应对照完成标准描述
- 遇到的问题应明确当前状态和建议下一步
- 代码变更应符合 `coding-standards` 规范

## 资源入口

- 编码规范：`../coding-standards/SKILL.md`（辅助能力，按需加载）

## V1 边界

本 V1 先解决：

- 按计划推进单个任务到完成
- 任务执行和状态记录闭环
- 与 coding-standards 的协同加载

本 V1 暂不解决：

- 多任务并行协调
- 自动化 CI/CD 流程触发
- 复杂代码审查流程
